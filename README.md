# 🛒 Telegram Auto-Sales Bot

Бот автоматических продаж на **Python + aiogram 3 + SQLite**:

- 🌆 Города и товары (админ-панель)
- 🛍 Каталог: название → описание + фото товара
- 🧺 **Корзина** (несколько товаров, в т. ч. из разных городов)
- 💼 **Баланс / кошелёк** — пополнение в TON / USDT (TRC-20) с подтверждением админом, оплата с баланса в один клик
- 💳 Внешняя оплата корзины криптой одной транзакцией
- 🚴 **Доставка курьером**: для каждого города назначается свой курьер; покупатель и курьер общаются прямо в боте, могут отправлять фото; кнопка «📦 Доставлено»
- ⚖️ **Диспуты**: покупатель открывает диспут, к чату подключается модератор; решение — «возместить (бесплатный заказ)» или «отклонить»
- 📜 История заказов и платежей
- 💬 **Отзывы**, видимые всем пользователям
- 🎁 «Бесплатный заказ» — выдаётся за выигранный диспут или вручную админом

## Стек

- Python 3.11+
- aiogram 3
- SQLAlchemy 2 + aiosqlite (async)
- python-dotenv

## Быстрый старт

```bash
git clone https://github.com/<owner>/telegram-sales-bot.git
cd telegram-sales-bot

python3 -m venv .venv
source .venv/bin/activate
pip install -e .

cp .env.example .env
# отредактируйте .env: BOT_TOKEN, OWNER_ID, ADMIN_IDS, MODERATOR_IDS, кошельки

python -m bot.main
```

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | токен от [@BotFather](https://t.me/BotFather) |
| `OWNER_ID` | ваш Telegram ID (главный админ + модератор) |
| `ADMIN_IDS` | дополнительные админы, через запятую |
| `MODERATOR_IDS` | модераторы диспутов, через запятую |
| `TON_WALLET` | адрес TON-кошелька для приёма платежей |
| `USDT_TRC20_WALLET` | адрес USDT-кошелька (TRC-20) |
| `DATABASE_URL` | строка подключения SQLAlchemy (по умолчанию SQLite-файл) |

Узнать свой Telegram ID можно командой `/id` у бота после первого запуска.

## Роли

- **Покупатель** — любой пользователь, написавший боту `/start`.
- **Админ** — указан в `ADMIN_IDS` или `OWNER_ID`. Имеет доступ к админ-панели: города, товары, курьеры, бесплатные заказы, проверка платежей.
- **Модератор** — указан в `MODERATOR_IDS`. Видит открытые диспуты, может принимать их и решать.
- **Курьер** — обычный пользователь, которого админ назначил на конкретный город. Один курьер на город. После назначения у него появляется «🚴 Кабинет курьера».

> ⚠️ Чтобы назначить пользователя курьером, он должен сначала запустить бота через `/start` — иначе его нет в БД.

## Денежные потоки

1. **Пополнение баланса** (`💼 Кошелёк → ➕ Пополнить`)
   — пользователь вводит сумму, выбирает TON/USDT, бот показывает кошелёк, пользователь шлёт перевод и присылает TX-хэш. Админ в `🧾 Платежи на проверке` подтверждает или отклоняет — баланс зачисляется автоматически.
2. **Покупка из корзины с баланса** — мгновенно, без подтверждения админа.
3. **Покупка из корзины внешним переводом** — создаётся заказ в `AWAITING_PAYMENT`, пользователь присылает TX, админ подтверждает; заказы переходят в `PAID`, курьеру города приходит уведомление с адресом.

## Структура

```
bot/
  main.py              # запуск, dispatcher, polling
  config.py            # .env, роли
  db.py                # async engine, session
  models.py            # User, City, Product, CartItem, Payment, Order, ChatMessage, Dispute, DisputeMessage, Review
  states.py            # FSM-состояния
  keyboards.py         # все inline-клавиатуры
  texts.py             # шаблоны текстов
  middlewares.py       # инжектирование сессии, апсерт пользователя
  utils.py             # helpers (роли, имена)
  handlers/
    common.py          # /start, /menu, /id
    catalog.py         # города → товары → карточка
    cart.py            # корзина и checkout
    balance.py         # кошелёк, пополнение
    orders.py          # история и просмотр заказов
    delivery.py        # курьер: принять/доставить, чат с покупателем (текст/фото)
    disputes.py        # открытие диспута, чат с модератором, разрешение
    reviews.py         # отзывы (создание + список)
    admin.py           # админ-панель
```

## CI

В репозитории настроен GitHub Actions workflow `ci.yml`, который ставит зависимости, прогоняет `ruff check` и проверяет, что бот импортируется и схема инициализируется в SQLite.
